## Changes

- Exact-frame source writer: bounded per-source queues, complete nonempty tails,
  private orphan/failure handling and atomic custody appends. Native startup,
  capture activation and consumer publication guards remain open; this adds no
  new runnable UI/MCP route. [Writer evidence](../verification/implementation-reports/2026-10-26-source-writer-foundation.md).

- Source-custody foundation: additive v16 bindings, atomic per-source/global
  checkpoints, exact-frame tails and durable quarantine/closure. Trusted native
  Rust APIs only; capture executor and consumer enforcement remain unintegrated.
  [Evidence and remaining gates](../verification/implementation-reports/2026-10-26-source-custody-foundation.md).
  The actual 44.1-kHz PID experiment also fails; no release waiver.

- Candidate source adds async read-only native route inventory and admission
  commands. They verify app/endpoint intent and provenance; multi-source capture
  execution and its UI are not yet integrated.

- Home → Live → Archive workflow with recording review and source controls.
- Explicit microphone, system loopback, and active-application process-loopback
  routing, with measured channel waveforms. Application capture never broadens
  to all-system audio automatically.
- CPU capture stores source audio first and transcribes after Stop to avoid
  decoder backpressure. Revisioned catch-up preserves source sequence boundaries.
- Application packet discontinuities preserve timeline gaps, and packet-read
  failures persist already captured audio before reporting failure.
- A bounded application-audio writer keeps filesystem work off the native reader;
  overflow remains an explicit failure instead of silently losing source audio.
- Microphone, system and application capture retain every nonempty audio tail.
- Terminal channel exits fail the capture job. Live and Archive Review show
  durable, recording-scoped capture warnings independently from recording lifecycle.
- Multichannel source export prepares separate microphone/system WAV artifacts
  from one validated completed-capture snapshot. Missing, changed, oversized or
  discontinuous source media fails the export job explicitly. Retries preserve
  stable media identities and the Archive inventory displays actual filenames.
- Windows system loopback retains native packet flags and initial/resumed idle
  time; normal CPU finalization waits for native completion instead of a fixed
  two-minute UI deadline.
- Application-session inventory runs in an owned MTA apartment; inventory errors
  are displayed separately from a successful empty list. Silent native packets
  are handled without dereferencing a nullable audio pointer.
- Post-meeting summary requires transcript; optional speaker diarization is
  dispatched only when its runtime is ready.
- New alternate app identities isolate default media roots; saved destinations
  and existing recordings are preserved.

## Runtime and limits

The candidate bundles portable CPython 3.11.9, faster-whisper 1.2.1 and a pinned
local large-v3-turbo model. Default transcription is local CPU int8. No system
Python, user model cache, CUDA installation, or model download is required for
the bundled baseline. Optional model/provider integrations require their own
setup. Transcript accuracy is not optimized or guaranteed by this release.

Windows installers are unsigned; SmartScreen may warn. Public distribution uses
the binary-only [FUNG-Releases](https://github.com/Freshair129/FUNG-Releases)
repository and the stable asset name `FUNG-windows-x64-setup.exe`. Approximate
download size is 1.5 GB; the published asset must have a verified exact SHA-256.

See [CPU timing decision](../decisions/2026-10-23-desktop-cpu-capture-priority.md)
and [capture evidence](../verification/implementation-reports/2026-10-23-capture-backpressure-remediation.md).
