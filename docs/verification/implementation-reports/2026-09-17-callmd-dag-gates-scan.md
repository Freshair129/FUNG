## 6. Safe scheduler rules

- A node is `READY` only when every dependency is accepted at the pinned SHA or
  digest, scope authority and approval exist, exact paths are resolved, the
  lease is free, no upstream gate is open, and capacity is available
  (`docs/plans/2026-09-17-callmd-ui-luna-max-dag-workflow.md:101-114`).
- Run at most three Luna workers. Parallel nodes must have disjoint exact or
  prefix-aware write sets. Shared contracts, schemas, DTOs, API bridges, CI,
  root styles, and integration files are serialized.
- A directory write such as `docs/design/callmd-desktop/` locks every path
  below that directory. Exact-file reuse is permitted only across a recorded
  dependency handoff, never across concurrent leases.
- If a dependency SHA, contract digest, input artifact, scope approval, or
  interface changes, mark all affected descendants `INVALIDATED`, cancel
  unconsumed leases, and re-review/retest them. Retain old evidence as
  historical; do not relabel it for the new revision
  (`docs/plans/2026-09-17-callmd-ui-luna-max-dag-workflow.md:122-124`).
- Worker output is `DONE`/`DONE_WITH_CONCERNS`/`NEEDS_CONTEXT`/`BLOCKED`; only
  Terra review can produce `PASS`/`WARN`/`FAIL`/`BLOCKED`, and `DONE` is not
  acceptance. A failure dispatches a fresh bounded Luna fixer, max three
  unsuccessful cycles, then escalates to Boss.
- The orchestrator may assemble clean, reviewed commits but does not repair
  implementation code. This scan made no commit or push.
